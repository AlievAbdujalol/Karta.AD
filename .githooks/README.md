# Conventional Commits в Karta.AD

Hook `commit-msg` проверяет формат сообщений и приводит их к
[Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/).

## Установка

Подключается автоматически при `npm install` (скрипт `prepare` в
package.json выполняет `git config core.hooksPath .githooks`). Вручную:

```bash
npm run hooks:install
```

## Формат

```
<тип>[(<область>)]: <описание>
```

Типы: `feat` `fix` `chore` `refactor` `test` `docs` `perf` `ci` `build`
`style` `revert` `security`.

## Примеры

```text
feat(taxi): заказ водителю из попапа на карте
fix(ai): кнопка чата не перекрывает панель навигации
security(ai-proxy): платные модели только с серверного разрешения
refactor(delivery): вынести расчёт цены в отдельный модуль
test(push): проверка генерации VAPID-ключей
docs(env): комментарии о ротации ключей в .env.example
chore(repo): не индексировать coverage/
```

## Правила

- Первая строка — заголовок, imperative mood, без точки в конце, ≤ 72 символов.
- Тело коммита (пустая строка + текст) — что и почему, не как.
- `!` перед `:` — ломающее изменение: `feat(api)!: новый формат ответа`.
- Нумерация задач: `fix(taxi): Closes #42` в теле.

## Что делает hook с нарушениями

1. Уже конвенциональное сообщение — пропускает.
2. Служебные git-сообщения (`Merge …`, `Revert …`) — пропускает.
3. Неизвестный тип (`bugfix: …`) — отклоняет с подсказкой.
4. Всё прочее (например, авто-сообщения внешней автоматизации
   `0.0.0.0.15.07`) — нормализует: добавляет подходящий тип
   (`test`/`docs`/`ci`, иначе `chore`), сохраняя исходный текст.

Строгий режим (отклонять без нормализации):

```bash
KARTA_STRICT_COMMITS=1 git commit -m "..."
```
