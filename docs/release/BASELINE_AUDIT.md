## 3. Подтверждённые дефекты

### RA-01 · P1 · Цена такси принималась с клиента (исправлено миграцией)

- **Где:** `src/pages/TaxiPassenger.jsx:715` (INSERT `price: selectedPrice`); триггер `trg_protect_taxi_order_price` — только `BEFORE UPDATE`.
- **Доказательство:** в транзакции с `ROLLBACK` от имени реального пассажира
  (`SET LOCAL ROLE authenticated`, `request.jwt.claims.sub = 3c565078-…`) INSERT
  с `price = 0.01`, `status = 'searching'` **принят** (вернулся `id`, `price 0.01`), затем `ROLLBACK`.
- **Ожидание:** сервер не принимает цену ниже разумной границы маршрута.
- **Факт:** цена полностью клиентская; `calculate_taxi_price` при INSERT не вызывалась.
- **Влияние:** пассажир может оформить поездку почти бесплатно; водитель видит заказ с ложной ценой.
- **Исправление:** `supabase/migrations/20261102040000_taxi_price_floor.sql` —
  триггер `BEFORE INSERT OR UPDATE`; нижняя граница считается по haversine
  (`calculate_taxi_price(расстояние, 0, категория, night=false) × 0.8`), админ — без ограничения.
- **Проверка безопасности фикса:** 102 исторических заказа с координатами — **0** ниже границы 0.8× (минимум 6.00 TJS).
- **Тест:** `src/test/publicOrdersPolicy.test.js` (структура миграции); прод-проба — вручную, см. выше.

### RA-02 · P1 · Навигация замирала после GPS-разрыва (исправлено)

- **Где:** `src/lib/NavigationContext.jsx:260` (до фикса): `if (jump > 150) return;`.
- **Доказательство:** RED-тест `src/test/navigationContext.test.jsx` — после 10 с без фиксов и реальных 400 м позиция оставалась `69.2` вместо `69.2046` (400 м не применялись). После возврата старого порога тест падает; с фиксом — проходит.
- **Ожидание:** после туннеля/фона навигация догоняет текущую позицию.
- **Факт:** все последующие фиксы сравнивались со старой точкой и тоже отклонялись — позиция замирала навсегда.
- **Исправление:** `isPlausibleGpsJump(jumpM, gapMs)` в `src/lib/navigationLogic.js` —
  скачок >150 м отклоняется только при физически невозможной скорости (>55 м/с ≈198 км/ч);
  учитывается интервал между фиксами.
- **Тесты:** 4 unit-теста в `navigationLogic.test.js`, 1 сценарий в `navigationContext.test.jsx`.

### RA-03 · P1 · Дубли заказов такси (исправлено)

- **Где:** `src/pages/TaxiPassenger.jsx:662` (`handleOrder` без блокировки), кнопка — только по `fromText/price`.
- **Доказательство (статическое):** в `handleOrder` нет ни блокировки повторного
  входа, ни idempotency-key; кнопка не блокируется на время запроса. Серверного
  ограничения нет: `pg_indexes` по `taxi_orders` не содержит уникального индекса
  по `passenger_id`, а RLS проверяет только `passenger_id = auth.uid()`.
  Воспроизведение двойного тапа в браузере не выполнялось (нет живого аккаунта).
- **Влияние:** два заказа в общем поиске, путаница водителей, лишние push.
- **Исправление:** `20261102030000_taxi_one_active_order.sql` — частичный уникальный индекс
  `(passenger_id) WHERE status IN ('searching','found','en_route','arrived','riding')`;
  клиент — `placingOrderRef` + `disabled` при `orderState !== 'idle'`.
- **Данные:** в прод активных заказов и дублей нет — индекс создаётся без конфликтов.
- **Тест:** `publicOrdersPolicy.test.js` (структура индекса).

### RA-04 · P2 · Публичные INSERT-политики заказов (исправлено как defense-in-depth)

- **Где:** `orders_insert_public`, `order_items_insert_public` (миграции `20261001000004`, `20261002000000`).
- **Доказательство:** политика разрешает `anon` INSERT, но фактическая проба
  (`SET LOCAL ROLE anon`, транзакция + `ROLLBACK`) **отклонена RLS**: подзапрос политики
  читает `businesses`, а у `anon` нет SELECT-политики на `businesses`. То есть это
  мёртвый код, а не активная дыра.
- **Риск:** если появится публичное чтение `businesses`, политика оживёт и откроет
  обход rate-limit (5 заказов/10 мин) и произвольный `delivery_price`.
- **Исправление:** `20261102020000_harden_public_orders.sql` — `DROP POLICY` для обеих;
  RPC `create_store_order` (SECURITY DEFINER) и её грант `anon` не тронуты.
- **Совместимость:** в проде 2 опубликованных AI-сайта используют `create_store_order`, 0 — прямой `/rest/v1/orders`.
- **Тест:** `publicOrdersPolicy.test.js`.

### RA-05 · P2 · Карточка «Вы прибыли» до подтверждения прибытия (исправлено)

- **Где:** `src/lib/NavigationContext.jsx:186` — при `arrive` и расстоянии ≤30 м возвращалось `L.arrive`.
- **Доказательство:** после одного GPS-фикса в 0 м от цели `hasArrived = false`, но карточка уже «Вы прибыли»; подтверждение требует 2 валидных замера. При плохой точности (>100 м) карточка оставалась ложной неограниченно.
- **Исправление:** карточка всегда нейтральная («Через X — пункт назначения»); «Вы прибыли» ставит только блок подтверждения прибытия.
- **Тест:** `navigationContext.test.jsx` — «карточка не объявляет прибытие до подтверждения».

### RA-06 · P2 · Тестовый платёж помечает заказ успешным (открыто, решение продукта)

- **Где:** `create_store_payment` (`SECURITY DEFINER`, EXECUTE у `anon`/`authenticated`),
  `src/lib/paymentProviders.js:42`; при `p_provider='mock'` статус сразу `succeeded`.
- **Доказательство:** функция не проверяет, кто инициировал платёж; любой клиент,
  зная `order_id`, может создать «успешный» платёж. Сумма берётся из заказа (не подделывается).
- **Влияние:** при включении реальных оплат это позволит отметить заказ оплаченным без денег.
  Сейчас реальные провайдеры `available: false`, чекаут — наличные/тестовый шлюз.
- **Рекомендация:** до подключения реальных провайдеров выключить `mock` в проде
  (флаг окружения/настройка бизнеса) или перенести создание платежа на серверный webhook.
- **Статус:** не исправлено — затрагивает продуктовый сценарий демо-оплаты.

### RA-07 · P3 · Трекинг заказа магазина по UUID (принятый риск)

- **Где:** `get_store_order_tracking(p_order_id)` — `SECURITY DEFINER`, доступна `anon`, окно 30 дней.
- **Факт:** возвращает статус, состав, суммы, адреса и координаты доставки, но не имя/телефон клиента.
- **Оценка:** UUID — bearer-токен, перебор невозможен; ссылка сама является секретом.
  Приемлемо для гостевого трекинга; при требовании строгой приватности — одноразовый токен, как в delivery.

### RA-08 · P3 · Кэш позиции в MapControls без проверки точности (открыто)

- **Где:** `src/components/MapControls.jsx:59` — кэш до 5 минут показывается как «Вы на карте» без проверки `accuracy`.
- **Факт:** в `Home.jsx` та же логика требует `accuracy ≤ 100 м`; здесь — нет.
- **Влияние:** на устройстве с грубым сетевым фиксом карта может прыгнуть на неточную точку.
- **Статус:** не исправлено (ветка используется только без `onLocate`; Home передаёт свой обработчик). Кандидат в P3-бэклог.

### RA-09 · P3 · `spatial_ref_sys` без RLS (принятый риск)

- **Факт:** единственная таблица `public` без RLS — системная таблица PostGIS; advisor `rls_disabled_in_public`.
- **Оценка:** не содержит пользовательских данных; включение RLS может сломать PostGIS. Оставляем, фиксируем в `KNOWN_ISSUES`.

### RA-10 · P2 · Прод без защитных заголовков и с нулевым кэшем ассетов (исправлено)

- **Факт (проверено на `https://karta-ad.vercel.app` 02.11.2026):**
  `strict-transport-security` есть (Vercel по умолчанию), а
  `x-content-type-options`, `x-frame-options`, `referrer-policy`,
  `permissions-policy` — отсутствуют. Хэшированный
  `/assets/index-*.js` отдаётся с `cache-control: public, max-age=0,
  must-revalidate`, то есть браузер перепроверяет каждый ассет при каждом
  заходе, хотя имя файла содержит хэш содержимого.
- **Риск:** MIME-sniffing, кликджекинг во фрейме, утечка полного URL через
  `Referer` на сторонние домены (тайлы, OSRM, Nominatim), лишние
  ревалидации статики на мобильных сетях.
- **Исправление:** блок `headers` в `vercel.json` — `nosniff`,
  `SAMEORIGIN`, `strict-origin-when-cross-origin`,
  `geolocation=(self), camera=(self), microphone=()`,
  `same-origin-allow-popups` (нужен для `window.open` в шаринге) и
  `Cache-Control: public, max-age=31536000, immutable` для `/assets/*`.
- **Проверка:** `src/test/securityHeaders.test.js` — 8 статических тестов на
  конфиг; после деплоя `b16cc92` живые заголовки и `immutable`-кэш
  подтверждены на `karta-ad.vercel.app` (`TEST_RESULTS.md` §5.2, п.9–11).
- **Почему без CSP:** см. `KNOWN_ISSUES.md` KI-10 — карта и сторонние
  источники требуют отдельного прогона в `Report-Only`.
